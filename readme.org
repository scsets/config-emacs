* Document role

Installation, normal operation, smoke tests, and day-to-day operator
commands for this personal Emacs profile.

* Overview

Personal Emacs configuration for Emacs 30.2 and Emacs 31.x.

Uses built-in ~use-package~ for package declarations and el-get for
package fetching through the local ~:el-get~ keyword. Local el-get
recipes cover packages that do not have suitable upstream recipes. The
~no-littering~ package keeps data and cache files organized under =var/=
and =etc/=.

Reusable Emacs Lisp helpers live under =lisp/= (see *Local libraries*
below). Byte-compiled =~.elc~= files are gitignored.

* Structure

| File / directory  | Purpose                                    |
|-------------------+--------------------------------------------|
| =init.el=         | Main configuration (all settings)          |
| =early-init.el=   | Early initialization (GC, UI, packages)    |
| =lisp/=           | Reusable local Elisp libraries             |
| =bin/=            | Launch helpers (=emacs-gui=, =emacs-tty=, =emacs-diagnostic=) |
| =CHANGELOG.org=   | Changelog of manual fixes and changes      |
| =plan.org=        | Improvement roadmap and keybinding proposals |
| =tasks.org=       | Outstanding and completed tasks              |
| =status.org=      | Current configuration health status        |
| =insights.org=    | Technical notes and lessons learned         |

No =custom.el= in the repository — all lasting settings live in
=init.el= / =lisp/=.  ~custom-file~ is redirected under
~temporary-file-directory~ so Customize never pollutes Git.  That file
is *intentionally disposable and never loaded*: treat the Customize UI
as inspection-only, and copy any wanted values into source.

* Trust boundary (Org)

This profile treats *your* Org files as trusted:

- ~org-export-allow-bind-keyword~ is on
- ~org-confirm-babel-evaluate~ is nil
- Babel backends include shell, Python, SQL, C, Lisp, and others

Do *not* evaluate or export downloaded, emailed, cloned, or otherwise
untrusted Org files in this profile.  Use ~emacs -Q~,
=bin/emacs-diagnostic=, or a separate safe profile for untrusted
material.

~howm-mode~ is enabled only for Org files under ~howm-directory~
(=~/notes=), not for every Org buffer.

* Local libraries (=lisp/=)

=init.el= adds =lisp/= to ~load-path~ once at startup. Each library
~NAME.el~ must end with ~(provide 'NAME)~ and is loaded with
~(require 'NAME)~ or an autoload.

| Library | Loaded from | Purpose |
|---------+-------------+---------|
| =org-tools.el= | ~require~ after Org; Hyper prefix autoload | Buffer helpers (header, creation-date, zwsp, rename) + export (line-prefix, stationery, PDF/X) |
| =scs-command-hub.el= | autoload ~scs/command-hub~; ~C-c ?~ / ~C-c /~ | Transient home: workflows, describe; Vertico catalog |
| =scs-config-sync.el= | autoload ~scs/sync-emacs-config~ | git pull this repo, prune leftover el-get, optional restart |
| =scs-frame-state.el= | autoload | Frame geometry save/restore |
| =scs-tramp.el= | TRAMP ~:config~ + autoload | Known hosts, cleanup, no-trace policy |
| =flycheck-org-lint-workaround.el= | ~flycheck~ block | Advice for broken Flycheck/org-lint line-cell handling |

** Frame Geometry Save/Restore

To save the selected frame's geometry under a label so it can be restored
after an Emacs restart or machine reboot:

#+begin_example
M-x scs/frame-state-save
#+end_example

The command prompts for a label and defaults to the current pixel
geometry, e.g. =1440x900+0+25=.  All saved geometries are written to the
same readable file, =var/frame-state.el=, as an alist of labeled entries.

After rebooting and starting Emacs again, restore with:

#+begin_example
M-x scs/frame-state-restore
#+end_example

See =insights.org= for property-drawer behaviour, the ~H-c~ Hyper prefix,
and the Karabiner + ~key-translation-map~ workaround for macOS Fn+C /
Control Center and Fn+H / Show Desktop.

* Minibuffer (Vertico + Orderless + Consult + Embark)

Helm is not loaded.  The minibuffer stack is Vertico (UI), Orderless
(matching), Consult (commands), Embark (~C-.~ actions).

| Job | Key | Command |
|-----+-----+---------|
| Open a path / new file | ~C-x C-f~ / ~H-f~ | ~find-file~ + Vertico (second press quits) |
| Jump by file name | ~M-s d~ | ~consult-fd~ |
| Switch buffer | ~C-x b~ / ~H-b~ | ~consult-buffer~ (second press quits) |
| Imenu | ~M-g i~ / ~H-i~ | ~consult-imenu~ (second press quits) |
| Line in this buffer | ~M-s l~ | ~consult-line~ (second press quits) |
| Content in the tree | ~M-s r~ | ~consult-ripgrep~ (second press quits) |
| Kill ring | ~M-y~ | ~consult-yank-pop~ |
| M-x | ~M-x~ / ~H-x~ | ~execute-extended-command~ (second press quits) |
| Minibuffer history | ~M-s~ / ~M-r~ in a prompt | ~consult-history~ |
| Last command (with args) | ~C-c h~ / ~C-x M-:~ | ~scs/consult-history~ / ~consult-complex-command~ |
| Actions on a candidate | ~C-.~ | ~embark-act~ |
| Repeat last completion | ~M-R~ | ~vertico-repeat~ (Helm-resume analogue) |

~C-x f~ is Emacs ~set-fill-column~ again.  ~M-s o~ is ~occur~; prefer ~M-s l~.
~C-x C-b~ is ~ibuffer~ (remap of ~list-buffers~).

Every Vertico prompt (Consult, ~M-x~, ~find-file~, the command hub
catalog) keeps a panel about half the selected window, even for one
hit.  Marginalia adds descriptions at the right; ~M-A~ in the
minibuffer cycles how much detail.  which-key popups may use up to
half the frame as well.

Narrowing inside Consult: type ~<~ then a letter (see ~consult-narrow-key~).
Orderless: space-separated tokens in any order, e.g. ~init el~.
~consult-buffer~ Files (~f~ after ~<~) comes from ~recentf-mode~.
A second press of M-x, ~find-file~, or the same Consult command
dismisses that prompt.  A different command from inside a prompt still runs
(minibuffer ~M-s~ history, Embark).  ~H-g~ is
~keyboard-escape-quit~ (same as ESC ESC ESC).  Project search is
~M-s r~; stock ~grep~ is ~M-x grep~.
Minibuffer ~M-s~ / ~M-r~ history comes from ~savehist-mode~.
~C-c h~ in Eshell or a prompt is ~consult-history~.  In Org and other
editing buffers it is ~consult-complex-command~ (replay a command with
its arguments).  ~M-R~ repeats the last Vertico session (same input and
candidate).  Last ~M-x~ commands also sort to the top of a new ~M-x~.

Edit many grep hits: ~M-s r~ (or ~M-s g~), then ~C-.~ ~A~ to export a
grep buffer, then ~C-c C-p~ for wgrep (or ~e~ for Emacs 31
~grep-edit-mode~).  ~C-c C-e~ applies wgrep edits; ~C-c C-k~ aborts.
~consult-line~ exports to occur the same way; ~e~ there is
~occur-edit-mode~.

In the command hub (~C-c ?~ / ~C-c /~), press ~q~ at any nesting level
to leave the whole Transient stack.  ~C-g~ still backs up one level.
Catalog browse (~c~) uses completing-read / Vertico.

First-run note: if the =el-get/el-get= checkout is missing, startup clones
it over the network.  That is intentional for a single-user profile.

* Generated State

Generated runtime state belongs outside Git:

| Path / pattern          | Owner                  | Notes                         |
|-------------------------+------------------------+-------------------------------|
| =var/=                  | no-littering, Org, TRAMP, recentf | Ignored; persistent local state |
| =var/frame-state.el=    | =scs-frame-state.el= | Ignored; saved frame geometry for reboot-safe restore |
| =var/org/id-locations.el= | org-id | Ignored; rebuilt with ~scs/org-id-rebuild~ |
| =eln-cache/=            | native compilation     | Ignored; safe to delete after Emacs/GCC upgrades |
| =el-get/=               | el-get | Ignored; package checkouts |
| =*.elc=                 | byte compilation       | Ignored; source is authoritative |
| =.org-id-locations=     | legacy Org default     | Ignored; config uses =var/org/id-locations.el= |

~early-init.el~ sets ~load-prefer-newer~ so stale bytecode does not shadow
newer source if an ignored =~.elc~= file is accidentally left behind.

* Smoke Tests

Useful checks after startup-sensitive edits.  Note: ~--batch~ implies
~-q~, so Emacs will *not* auto-load this profile in batch mode.  Always
load =early-init.el= and =init.el= explicitly (do not ~-l init.el~ alone,
which skips early-init).

#+begin_src sh
# A. Isolated load of this profile (both files, once each)
emacs -Q --batch -l early-init.el -l init.el \
  --eval '(message "init time: %s" (emacs-init-time))'

# B. Paren structure only
emacs -Q --batch --eval "(progn
  (dolist (file (append (list \"early-init.el\" \"init.el\")
                        (directory-files \"lisp\" t \"\\\\.el$\")))
    (with-temp-buffer
      (insert-file-contents file)
      (emacs-lisp-mode)
      (check-parens))))"

# C. Daemon smoke (real GUI/server startup path); stop afterwards
emacs --fg-daemon=scs-config-smoke --debug-init
emacsclient -s scs-config-smoke -e '(progn (message "%s" (emacs-init-time)) (kill-emacs))'
#+end_src

Diagnostic launch (warnings visible; still loads this profile explicitly):

#+begin_src sh
bin/emacs-diagnostic
# or: bin/emacs-diagnostic --batch --eval '(message "%s" (emacs-init-time))'
#+end_src

* macOS Hyper keys

On macOS, Caps Lock is remapped to Fn (Karabiner) and Fn is Emacs
Hyper (~ns-function-modifier~). Most Hyper bindings are single-key
shortcuts (see =init.el=). ~H-c~ is a /prefix/ keymap:

| Chord     | Command                        |
|-----------+--------------------------------|
| ~H-c c~   | ~org-capture~                  |
| ~H-c d~   | ~scs/org-insert-creation-date~ |
| ~H-c H-d~ | ~scs/org-insert-creation-date~ |

~H-c d~ (plain ~d~ after the prefix) is the usual creation-date chord;
~H-c H-d~ also works. Both require Org mode; the command errors
elsewhere.

macOS steals raw Fn+C (Control Center) and Fn+H (Show Desktop).
Karabiner rewrites those chords inside Emacs to proxy chords; ~init.el~
translates them back to ~H-c~ / ~H-h~.  See =insights.org= (*Hyper
chords that macOS steals*) for the rules, ~key-translation-map~
entries, and the ~C-M-s~ vs ~C-M-S~ pitfall.
