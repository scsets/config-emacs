* Curated GUI startup (not desktop.el)

~desktop-save-mode~ is off in this profile.  Graphic Emacs opens a
small home screen from ~lisp/scs-startup-state.el~:

- Restore one named entry from ~scs-frame-state~
  (~scs/startup-state-frame-label~, default ~2048x1127+0+25~)
- Visit ~scs/startup-state-files~ (seed: =~/notes/progress-todo.org=
  and =~/.config/emacs/init.el=)
- Left/right split for the first two existing files; further files
  load with ~find-file-noselect~ only

Terminal / ~emacs -nw~ skips the module (~display-graphic-p~ gate).
Bookmarks stay for jumping only; they are not startup markers.

Apply runs on ~window-setup-hook~ (and once for the first graphic
~emacsclient~ frame via ~after-make-frame-functions~).  Re-run by hand
with ~M-x scs/startup-state-apply~ (prefix arg forces after the
once-per-session flag).

Spec: =docs/2026-08-04-startup-state-design.org=.

* Command hub: Transient + curated data

Remembering that a command exists is a different job from remembering
the next key after a prefix.  which-key already covers the latter.
For the former, this profile uses a Transient home on ~C-c ?~ or
~C-c /~ (same command; ~/~ needs no Shift) via ~lisp/scs-command-hub.el~
over a curated plist catalog.  completing-read (Vertico) searches
titles and summaries; nested Transients hold small sticky workflows
(Org, TRAMP, frames); helpful (with ~describe-*~ fallback) opens
deeper docs.

The catalog is plain data on purpose: Approach C (a thicker local
dispatcher) or a later Hydra trial can reuse the same list without a
rewrite.  Grow an entry when something is forgotten once.

This profile maps ~C-h~ / ~M-h~ to delete globally and keeps Emacs
help on ~F1~.  Package UIs that want a help prefix must not steal
~C-h~ (Embark during ~embark-act~ is the current example; Helm used
to be another).

Transient menus use a bottom side window with brighter heading/key
faces so groups and semantic key colors (stay / exit / recurse) are
easier to read.  Transient itself always *fits* that window to the
menu text, which is why a plain ~window-height~ setting looked like a
minibuffer for short hubs.  This profile advises
~transient--fit-window-to-buffer~ via ~scs/transient--enforce-min-height~
and grows the window to ~scs/transient-min-height-fraction~ (default
0.28 of the frame, at least 10 lines).  Faces live in the ~transient~
~use-package~ block.

* Emacs 30 strict plist checking

In Emacs < 30, ~plist-put~ on a non-plist (like a string) silently
created a new plist and discarded the original value — it "worked" by
accident. Emacs 30 added strict type checking for plist operations, so
passing a string now signals ~wrong-type-argument plistp~. Any
third-party code that relied on this leniency will break on upgrade.

When patching =.el= files managed by package managers like el-get,
always delete the corresponding =.elc= — Emacs loads bytecode
preferentially, so a stale =.elc= silently ignores your source fix.

* Unicode smart quotes in Emacs Lisp

The character =' (U+2018, LEFT SINGLE QUOTATION MARK) looks like a
quote but is a multi-byte Unicode character. Emacs Lisp reads it as a
symbol name, not as the ~quote~ special form.  This means ~'foo~
produces the symbol ~'foo~ (with the curly quote as part of the name)
rather than ~(quote foo)~.

Common source: pasting code from web pages, PDFs, or rich-text editors
that auto-convert ASCII quotes to typographic quotes.

* Portable home directory paths

Emacs resolves =~= to the user's home directory via ~expand-file-name~
internally. This works on macOS (=/Users/scs=), Linux (=/home/scs=),
and Windows (=C:/Users/scs=). Using =~/= instead of hardcoded absolute
paths makes configs portable across machines and usernames.

For paths consumed by external programs (like ~inferior-lisp-program~),
wrapping with ~expand-file-name~ ensures =~= is resolved to an absolute
path immediately, which is safer for subprocess invocation.

* no-littering for data file paths

Rather than defining custom helper functions (like ~user-data~) for
locating data files, use ~no-littering-expand-var-file-name~ (for
variable/state data) and ~no-littering-expand-etc-file-name~ (for
configuration data). These place files under =var/= and =etc/=
subdirectories respectively, keeping the Emacs directory clean.

* Consolidating package managers for a single package

When a package is loaded by both ~package.el~ (via ~:ensure~) and
~el-get~ (via ~el-get-bundle~), Emacs warns about the conflict at
startup. The fix is to choose one manager per package. For packages
like ~org-contrib~ that provide multiple features (~ob-ly~,
~org-expiry~, etc.), a ~use-package~ block with ~:config~ that
requires the sub-features is cleaner than scattered ~require~ calls,
because it centralizes the dependency and makes the load order explicit.

Avoid ~:ensure pkg~ on a /different/ package's ~use-package~ block
(e.g., ~:ensure org-contrib~ inside ~(use-package org ...)~) — this
installs the package but doesn't configure it. Give it its own block.

* RCS keyword expansion

RCS expands keywords on check-in (~ci~). The keyword pattern
(dollar-sign + name + dollar-sign) must be present in the working file
before the first check-in. Once expanded, RCS recognizes and
re-expands it on subsequent check-ins automatically.

*Caution:* RCS expands /every/ matching keyword pattern in the file,
including ones in documentation text. Avoid writing literal keyword
patterns in body text — they will be expanded and mangled on check-in.

Useful keywords (by name):
- *Id* — filename, revision, date, author, state, locker
- *Log* — accumulates commit messages (can bloat files)
- *Date*, *Author*, *Revision* — individual fields

Emacs VC mode (~C-x v v~) auto-detects RCS and handles check-in/out.

* early-init.el save-and-restore pattern

Setting ~file-name-handler-alist~ or ~vc-handled-backends~ to ~nil~
during startup is a common optimization, but you /must/ save the
original value beforehand and restore it in ~emacs-startup-hook~.
Failing to restore ~file-name-handler-alist~ breaks TRAMP (remote file
access), compressed file reading (=.gz=, =.bz2=), and any filename
"magic" (e.g., =jka-compr=). Failing to restore ~vc-handled-backends~
disables all version control detection permanently.

The safe pattern is:

#+begin_example
(defvar my--saved-fha file-name-handler-alist)
(setq file-name-handler-alist nil)
(add-hook 'emacs-startup-hook
          (lambda () (setq file-name-handler-alist my--saved-fha)))
#+end_example

* Why move UI settings to early-init.el

Emacs evaluates ~early-init.el~ /before/ creating the initial frame.
Settings like ~(tool-bar-mode -1)~ placed in ~init.el~ cause the
toolbar to first appear (frame creation) then disappear (init.el
loads), producing a visible flicker. In ~early-init.el~, the mode is
disabled before the frame exists, so the toolbar never draws at all.

Similarly, ~package-initialize~ in ~early-init.el~ means packages are
available immediately when ~init.el~ starts, eliminating the need for
~package-enable-at-startup~ juggling.

* Cross-platform predicates: system-type vs window-system vs display-graphic-p

Three predicates serve different cross-platform purposes:

- ~system-type~ — identifies the OS kernel: ~'darwin~ (macOS), ~'gnu/linux~,
  ~'berkeley-unix~ (FreeBSD), etc. Use for OS-specific variables like
  ~mac-command-modifier~ that exist only in macOS Emacs builds.

- ~window-system~ — identifies the display backend for the /current frame/:
  ~'ns~ (macOS GUI), ~'x~ (X11), ~'w32~ (Windows), ~nil~ (terminal).
  Use for frame-parameter settings specific to a display system, e.g.
  ~undecorated-round~ is NS-only.

- ~(display-graphic-p)~ — returns non-nil when the /current frame/ is a GUI
  frame (any backend), ~nil~ in terminal (~emacs -nw~) and ~--batch~ modes.
  Use for features that require a graphical display (toolbar, pixel
  scrolling, frame naming).

- ~initial-window-system~ — the window system Emacs was /started with/
  (~'ns~, ~'x~, ~'pc~, or ~nil~). Available during ~early-init.el~, before
  the display connection exists.

Rule of thumb: start with ~display-graphic-p~ (broadest GUI check), narrow
to ~window-system~ for display-backend specifics, use ~system-type~ for
OS-level concerns independent of display.

** Exception: ~early-init.el~ runs before the GUI exists**

~early-init.el~ is loaded *before* ~window-system-initialization~ and
*before* the initial frame is created. At that point there is no graphic
frame yet, so ~(display-graphic-p)~ is ~nil~ even when you launched GUI
Emacs from the Dock or terminal.

Do /not/ wrap ~early-init~ hook registration in ~(when (display-graphic-p)
...)~ — the hooks will never be added and startup-only logic silently
does nothing (while the same functions still work when called manually
later via ~M-:~).

Use ~(when (and initial-window-system (not noninteractive)) ...)~ instead.
The same applies to NS-only ~default-frame-alist~ entries such as
~undecorated-round~: test ~initial-window-system~, not ~window-system~
(which is also ~nil~ during ~early-init~).

* Half-screen frame geometry at startup (macOS GUI)

Goal: every graphic frame at top-left of the monitor workarea, half
width, full usable height (minus a small inset).

Implemented in ~early-init.el~ (~scs/frame-apply-half-screen-geometry-*~).

** Monitor metrics**

Use ~frame-monitor-attributes~ and prefer the ~workarea~ field (usable
area below the menu bar, above the dock). Do not fall back to
~display-pixel-height~ when workarea is unavailable — that value is the
full display and is both too tall and wrong for positioning. Retry
until workarea is reported (macOS often returns ~nil~ on the first hook
invocation).

** Startup hook order**

Emacs applies user frame settings late in startup:

1. ~emacs-startup-hook~
2. ~frame-notice-user-settings~ (reapplies ~initial-frame-alist~ /
   ~default-frame-alist~ to the initial frame)
3. ~window-setup-hook~

Geometry and curated startup (~scs/startup-state-apply~) must run on
~window-setup-hook~, not only on ~emacs-startup-hook~.  (Older notes
mentioned ~desktop-after-read-hook~ when ~desktop-save-mode~ was on;
desktop is no longer used -- see *Curated GUI startup* above.)
Scheduled retries (~run-at-time~ at 0–3 s) cover late monitor data on
NS when a half-screen helper is active.

** Resize API (~frame-resize-pixelwise t~)**

With pixelwise resizing enabled:

#+begin_example
(set-frame-position nil x y)           ; 3 args only — not 4
(set-frame-size nil width height t)    ; 4th arg t means pixels
#+end_example

There is no ~set-frame-pixel-size~ in Emacs 30. Passing a fourth
argument to ~set-frame-position~ signals ~wrong-number-of-arguments~.

** Height inset**

~scs/frame-height-inset~ (default 24 px) is subtracted from workarea
height so the frame does not extend slightly past the visible area
(menu bar / ~undecorated-round~ rounding).

* auto-save-list-file-prefix void at startup

Symptom when launching from the CLI:

#+begin_example
normal-top-level: Symbol's value as variable is void: auto-save-list-file-prefix
#+end_example

~auto-save-list-file-prefix~ is a ~defcustom~ with
~custom-initialize-delay~: it stays /unbound/ until Emacs evaluates its
standard value during the delayed-init batch in ~command-line~. Near the
end of ~normal-top-level~, an ~unwind-protect~ body references the
variable to build ~auto-save-list-file-name~.

** Root cause observed**

Launching Emacs with the shell's current working directory set to a path
that *no longer exists* (directory deleted after ~cd~ into it). Broken
~default-directory~ at startup can prevent delayed custom variables and
path-dependent initialization from completing, leaving
~auto-save-list-file-prefix~ void when ~normal-top-level~ unwinds.

Fix at the shell: ~cd ~ RET~ (home) or ~cd~ into any existing directory
before ~emacs~. Launching from the Dock or Spotlight avoids the issue
because no stale cwd is inherited.

** Defensive init (~early-init.el~)**

After ~user-emacs-directory~ is set, force initialization:

#+begin_example
(when (fboundp 'custom-reevaluate-setting)
  (custom-reevaluate-setting 'auto-save-list-file-prefix))
#+end_example

~no-littering~ in ~init.el~ relocates the prefix again under ~var/~; that
runs later and is independent of this safeguard.

* executable-find for optional external tools

Wrapping configuration for external programs in ~(executable-find "prog")~
makes the config portable: settings are silently skipped on systems where
the tool isn't installed, avoiding "Searching for program: No such file or
directory" errors. This is especially useful for tools like ~aspell~,
~ugrep~, and ~rg~ that may not be present on all platforms.

* use-package :custom evaluates at expansion time

The ~:custom~ keyword in ~use-package~ calls ~customize-set-variable~
at *macro expansion time* — the value expression is evaluated
immediately when init.el is byte-compiled or loaded, NOT when the
package is lazily triggered via ~:commands~ or ~:defer~.

This means function calls in ~:custom~ values must reference code
that is *already loaded*:

#+begin_example
;; WRONG — no-littering may not be loaded yet when eshell :custom runs
(use-package eshell
  :commands eshell
  :custom
  (eshell-directory-name (no-littering-expand-var-file-name "eshell/")))

;; RIGHT — locate-user-emacs-file is always available (built-in)
(use-package eshell
  :commands eshell
  :custom
  (eshell-directory-name (locate-user-emacs-file "var/eshell/")))
#+end_example

Alternative: move the setting into ~:config~ (which runs after the
package loads and all prior init has completed).

* Quoted vs unquoted lambdas

Writing ~'(lambda ...)~ (with a quote) prevents byte-compilation and
makes the closure opaque to the compiler. In modern Emacs (24+),
~(lambda ...)~ is self-quoting — always use the unquoted form:

#+begin_example
;; WRONG
(define-key global-map (kbd "<S-f9>") '(lambda () (interactive) ...))

;; RIGHT
(define-key global-map (kbd "<S-f9>") (lambda () (interactive) ...))
#+end_example

* use-package :vc and package-vc

Emacs 30's built-in ~use-package~ supports the ~:vc~ keyword. It
installs packages through ~package-vc~ and accepts package source
plists such as:

#+begin_example
(use-package package-name
  :vc (:url "https://example.invalid/package-name.git"
       :rev :newest))
#+end_example

Supported source keys include ~:url~, ~:branch~, ~:lisp-dir~,
~:main-file~, ~:vc-backend~, ~:rev~, ~:shell-command~, ~:make~, and
~:ignored-files~. If ~:rev~ is omitted, use-package defaults to the
latest release. Use ~:rev :newest~ when tracking the latest commit is
intentional.

In Emacs 30.2, ~use-package-handler/:vc~ calls
~use-package-vc-install~, which checks ~(package-installed-p name)~
before calling ~package-vc-install~. That means a normal ~:vc~
declaration installs on first load and does not reinstall on every
startup.

The older startup-loop problem came from calling ~package-vc-install~
directly at top level:

#+begin_example
;; Avoid this pattern unless it is guarded.
(package-vc-install '(framemove :url "https://..."))
#+end_example

If a direct install call is needed, keep the explicit guard:

#+begin_example
(unless (package-installed-p 'framemove)
  (package-vc-install '(framemove :url "https://...")))
#+end_example

VC-installed packages still use package metadata and archive packages
for dependencies. Keep ~package-install-upgrade-built-in~ enabled in
=early-init.el= so dependencies can upgrade bundled packages when a
newer archive version is required.

When a dependency exists in multiple archives, avoid pinning it unless
the preferred source really matters. Most pure Emacs Lisp dependencies
can come from MELPA or an ELPA archive when ~package-refresh-contents~
has current metadata, so this config leaves them unpinned and lets
archive priority choose.

If early-init temporarily sets ~vc-handled-backends~ to nil for startup
speed, first-run ~:vc~ installs need it restored before the
~use-package~ declaration expands at runtime. A targeted guard is best:
restore VC only when one of the VC-installed packages is missing, then
let the normal startup hook restore the value on later starts.

For SmartOS/illumos, verify any external helper before relying on
automatic downloads. Prefer a separately installed executable on PATH
unless the package's upstream download path is known to support illumos.

For interactive packages, add the public entry points under
~:commands~. This preserves lazy loading while keeping =M-x= command
discovery useful.

* RCS lock workflow: rcs -l then ci -u

After ~ci -u~ (check in, unlock), the working file is read-only and
unlocked.  The safe cycle for subsequent edits is:

1. ~rcs -l file~ — lock the file *without* overwriting the working copy.
   This is critical: it preserves your local changes while acquiring
   the lock needed for check-in.
2. Edit the file.
3. ~ci -u -m"message" file~ — check in and immediately unlock, leaving
   the working file in place with updated RCS keywords.

*Why not ~co -l~?*  The ~co -l~ command checks out the /repository/
version and *overwrites* the working file.  If you have local edits
that haven't been checked in, they are silently destroyed.  Always
use ~rcs -l~ to lock an existing working file.

For batch check-ins (multiple files, same message):

#+begin_example
for f in init.el CHANGELOG.org status.org; do
  rcs -l "$f" && ci -u -m"commit message" "$f"
done
#+end_example

* Dual Emacs server: sockets + TCP

Emacs supports multiple server instances by varying ~server-name~.
Using ~let~ to dynamically bind ~server-name~ and ~server-use-tcp~
around a second ~server-start~ call creates an independent server
without altering the global defaults.

Unix domain sockets (the default) work on all Unix-like platforms
(macOS, FreeBSD, SmartOS/illumos) and are what ~emacsclient~ looks
for automatically. TCP mode requires passing ~-f~ / ~--server-file~
to ~emacsclient~ with the path to an auth file.

Pattern:

#+begin_example
;; Default server: Unix socket (works with plain emacsclient)
(server-start)

;; Second server: TCP for apps that need it
(let ((server-name "scrim")
      (server-use-tcp t))
  (unless (server-running-p "scrim") (server-start)))
#+end_example

** TCP auth files vs Unix sockets

TCP mode creates a plain /auth file/ (containing IP, port, and auth
key) in ~server-auth-dir~.  Socket mode creates a Unix domain /socket
file/ in ~server-socket-dir~.  They look different on disk:

- Auth file: regular file (e.g. =server/scrim=), contains ~127.0.0.1:56242 70858 ...~
- Socket: socket file (=srwx------=) in the ~server-socket-dir~ tmpdir.

~no-littering~ redirects ~server-auth-dir~ but not ~server-socket-dir~,
so TCP auth files land under =var/server/auth/= while sockets still go
to the OS tmpdir (e.g. =/var/folders/.../emacs501/=).

** server-start and stale server files

~server-start~ will prompt interactively ("server file already exists;
delete it?") if it finds a leftover auth file or socket from a
previous session.  This blocks daemon startup.  If switching from TCP
to sockets (or vice versa), delete stale files before restarting, or
call ~(server-force-delete)~ first.

** emacsclient -a "" for daemon auto-start

Passing ~-a ""~ (empty string as alternate editor) tells ~emacsclient~
to start a new Emacs daemon if no server is found, then retry the
connection.  Combined with ~-n~ (no-wait), this is a reliable way to
ensure an Emacs server is always available from scripts or MCP tools:

#+begin_example
emacsclient -n -a "" -e '(emacs-version)'
#+end_example

*Caution:* the ~-a~ flag must be separated from its argument; combined
forms like ~-nwa ""~ cause argument parsing errors on some builds (the
parser reads ~""~ as the timeout for ~-a~ instead of the alternate
editor string).

* org-id for howm notes

The howm creation hook adds an ~:ID:~ property to new howm notes,
making them discoverable via ~org-id~ and linkable with standard
~[[id:...]]~ links.

The ~(org-mode . howm-mode)~ hook enables howm's action-lock minor
mode in all org buffers, so comefrom links (~<<< keyword~) work
everywhere — not just in files opened through howm.

Populating ~org-id-extra-files~ with ~directory-files-recursively~
on the howm directory ensures that ~org-id-goto~ can jump to any
howm note by ID, even if it was never opened in the current session.

* Semantic howm filenames via after-save-hook

Howm's ~howm-file-name-format~ only supports ~strftime~ codes — it
cannot include the note title or tags because those don't exist when
the file is first created.  The workaround is an ~after-save-hook~
that renames the file once the content is known.

Key implementation details:

- Use ~set-visited-file-name~ with the third argument ~t~
  (~along-with-file~) to tell Emacs the file was already renamed on
  disk.  This avoids an infinite save loop since the rename happens
  inside ~after-save-hook~.
- Guard with ~file-in-directory-p~ to only rename files in the howm
  directory, not every org buffer.
- Check ~(not (file-exists-p new-path))~ before renaming to avoid
  clobbering an existing note with the same slug.
- Use ~y-or-n-p~ to let the user decline the rename, preserving the
  original filename when the title change was incidental.

This pattern is similar to ~denote~'s filename convention
(=DATE--TITLE__KEYWORDS.org=), adapted for howm with ~_~ as the
field separator.

* Stale MELPA archive cache and transitive dependencies

MELPA is a rolling-release archive — packages get new version
timestamps on every commit.  The local package archive cache (built
by ~package-refresh-contents~) stores download URLs with specific
version strings.  If a transitive dependency gets a new release
between cache refreshes, the cached URL 404s with "Not found", even
though the package still exists on MELPA.

Fix: run ~package-refresh-contents~ (or ~M-x package-refresh-contents~)
to rebuild the cache, then retry the install.  For init.el resilience,
refresh only when an install is about to happen and the on-disk cache
is older than a chosen threshold:

#+begin_example
(defvar scs/package-archive-max-age (* 12 60 60))

(when (and (not (package-installed-p 'some-package))
           (scs/package-archive-stale-p))
  (package-refresh-contents))
#+end_example

This pattern avoids refreshing on every startup (slow) while
preventing old archive metadata from sending first-run package
installs to vanished MELPA tarballs.

* lexical-binding in init.el

Adding ~-*- lexical-binding: t -*-~ to the first line of =init.el=
enables lexical scoping. This is the modern Emacs default for new
files and is required by many packages. Without it, all variables use
dynamic binding, which can cause subtle bugs with closures and
~let~-bound variables in callbacks or hooks.

* Emacs Lisp case sensitivity

Emacs Lisp is case-sensitive for all symbol names. ~Set-input-method~
and ~set-input-method~ are completely different symbols. This is unlike
Common Lisp, which upcases symbol names by default via the reader.

When Emacs hits a ~void-function~ error during init, it aborts loading
the rest of the file. Everything after the error (packages, keybindings,
hooks) is silently skipped. Use ~emacs --debug-init~ to start Emacs with
the debugger enabled, showing exactly where and why init failed.

* RCS ci and file permissions

RCS ~ci~ (check-in) removes write permission by default. Using ~ci -u~
checks in and immediately checks out an unlocked (but readable) copy.
To keep the file writable afterward, run ~chmod u+w~ -- or use ~ci -l~
to keep the lock (file stays writable).

Emacs respects filesystem permissions: a file with mode 444 opens in
~read-only-mode~. The modeline shows ~%%~ instead of ~--~ to indicate
this. Use ~M-x revert-buffer~ after changing permissions externally.

* The Hyper modifier key as a free namespace

Most Emacs users run out of convenient keybindings because Control,
Meta, and Super are heavily used by Emacs and the OS. The Hyper
modifier (H-) provides an entirely free namespace of ~50+ keys that
never conflict with built-in Emacs bindings or OS shortcuts.

On macOS, mapping Caps Lock to Fn via Karabiner Elements, then setting
~ns-function-modifier~ to ~'hyper~, gives a comfortable Hyper key on
the home row. The bindings must be guarded with
~(when (eq system-type 'darwin) ...)~ since Hyper is not available on
other platforms without similar remapping. Fn+C is stolen by macOS
Control Center; Fn+H is stolen by Show Desktop.  See *Hyper chords that
macOS steals (Fn+C / Fn+H)* below for the Karabiner and
~key-translation-map~ fix used in this config.

A column-header comment above grouped ~global-set-key~ calls documents
the mnemonic for each binding at a glance, per the CLAUDE.md style for
repeated positional calls.

* corfu vs company

*Decision (2026-06-06):* company is the active in-buffer completion UI.
Corfu was tried and not adopted. Cape remains for manual capf via ~C-c .~.

Company and corfu solve the same problem (in-buffer completion popup)
but use different architectures:

- *company* maintains its own backend/frontend system. You configure
  ~company-backends~ and ~company-frontends~ separately. This is
  powerful but adds complexity and can conflict with Emacs's native
  completion.

- *corfu* uses Emacs's native ~completion-at-point-functions~ (capf)
  infrastructure directly. The same capf functions that power
  ~completion-at-point~ (M-TAB) also drive corfu's popup. This means
  corfu works with any mode that provides capf support, and stays
  independent from the minibuffer completion UI.

Cape (~completion-at-point-functions extensions~) adds additional capf
backends (dabbrev, file, history, etc.) that work with both company
and corfu. The ~cape~ configuration in init.el is preserved and works
with corfu unchanged.

* Vertico for minibuffer completion

Vertico owns the minibuffer completion UI.  Orderless is the matching
style.  Consult adds commands on ~completing-read~ (buffers, fd,
ripgrep, yank, history).  Embark (~C-.~) acts on the current
candidate.  Company still handles in-buffer popup completion; cape
supplies extra capf backends via ~C-c .~.

Keep only one minibuffer completion UI active at a time.  Helm was
removed on 2026-08-17 so it cannot steal ~completing-read~ or the
chords Consult documents.

* yasnippet and company-yasnippet

Yasnippet expands templates in-buffer (usually Tab on a trigger key).
Snippet names appear in the company popup via ~company-yasnippet~;
expansion still goes through yasnippet.  The minibuffer stack does not
drive snippets.

Personal snippets live in =~/.config/emacs/snippets/~, one subdirectory
per major mode (~org-mode~, ~emacs-lisp-mode~, ~lisp-mode~,
~text-mode~). A ~.yas-parents~ file lists modes whose snippets are
inherited; Org and both Lisp tables inherit ~text-mode~ (~isod~,
~time~, ~mail~).

Use ~add-to-list 'yas-snippet-dirs~ for the personal directory — do not
~setq~ over the whole list. Modern yasnippet ships without bundled
snippets; the personal tree is the collection.

~M-x yas-new-snippet~ writes into the first ~yas-snippet-dirs~ entry.
~M-x yas-describe-binds~ lists triggers for the current mode.

** Dynamic dates in snippet templates

Use backquotes for Elisp evaluated at expansion time, including inside
placeholder fields:

#+begin_example
#+date: ${3:`(format-time-string "%Y-%m-%d")`}
#+end_example

Do /not/ use ~${n:$(format-time-string ...)}~ — in yasnippet, ~${n:$(...)}~
starts with ~$(~ is parsed as a /mirror transformation/ on field ~n~
(using ~yas-text~), not as an initial value. That leaves the date empty
or wrong. The Org ~meta~ snippet (~meta~ → ~#+title:~ / ~#+author:~ /
~#+date:~) and shared ~isod~ / ~props~ / ~time~ snippets follow the
backquote form.

* BUG(helm): file-equal-p with nil backup-directory-alist cdrs [fixed upstream]

~no-littering-theme-backups~ sets valid ~backup-directory-alist~ entries
whose cdr is ~nil~. ~helm-ff--in-backup-directory~ used to call
~file-equal-p~ on every entry without checking ~f~, causing
~wrong-type-argument stringp nil~ during ~helm-find-files~.

Fixed in helm ~0aa89912~ (#2756):
~thereis (and f (file-equal-p f helm-ff-default-directory))~.
No local override in ~init.el~.

* eshell prompt and eshell-prompt-regexp

The eshell prompt function and ~eshell-prompt-regexp~ must stay in
sync. Eshell uses the regexp to determine where the prompt ends and
user input begins -- it's how eshell knows which text is editable vs
which is the prompt. If the regexp doesn't match the actual prompt
string, eshell's command detection, C-a behavior, and input
highlighting all break.

When changing the prompt to include hostname, the regexp
~"^[^#$\n]* [#$] "~ matches "anything up to the # or $ delimiter",
which works for both ~hostname:path $~ and the old ~path $~ format.

* eat vs vterm for terminal emulation

Both ~eat~ and ~vterm~ provide full terminal emulation inside Emacs.
The key difference is build requirements:

- *vterm* requires ~libvterm~ (a C library) and compiles a dynamic
  module (~vterm-module.so~) on first use. This fails on systems
  without a C compiler or where the library isn't packaged (common
  on SmartOS, some FreeBSD jails).

- *eat* is pure Emacs Lisp with no C dependencies. It works on any
  platform that runs Emacs. Performance is slightly lower for
  high-throughput terminal output, but sufficient for interactive use.

The ~(eat-eshell-mode)~ hook makes eat handle eshell's "visual
commands" (like htop, vim, less) inside the eshell buffer itself,
instead of spawning a separate ~*ansi-term*~ buffer.

* diff-hl in terminal mode

~diff-hl~ uses the fringe (the narrow strip beside the line numbers)
to show VCS change markers in GUI Emacs. In terminal mode (emacs -nw),
fringes don't exist. The ~diff-hl-margin-mode~ fallback uses the
margin (the area beside the line numbers, rendered with text
characters) instead. The guard:

#+begin_example
(unless (display-graphic-p)
  (diff-hl-margin-mode))
#+end_example

ensures the right mode is activated based on the display type. diff-hl
works with any VC backend supported by ~vc~ (Git, SVN, RCS, Hg, etc.),
not just Git.

* tramp-histfile-override

By default, TRAMP runs a login shell on the remote host, which reads
~.bash_history~ / ~.sh_history~ and appends commands to it. This means
your remote shell history fills up with TRAMP's internal probe commands
(~test -e /bin/sh~, ~stty~ calls, etc.).

Setting ~tramp-histfile-override~ to ~t~ makes TRAMP set ~HISTFILE~ to
~/dev/null~ for its shell sessions, keeping remote history clean. The
user's normal SSH sessions still use the real history file.

* Emacs Lisp hex escapes vs Unicode escapes in strings

Emacs Lisp string escape sequences operate at the *character* level,
not the byte level. This distinction matters for non-ASCII characters:

- ~\xNN~ creates a character with code point NN (one character).
  ~"\xef\xbf\xbd"~ creates *three* characters with code points
  0xEF, 0xBF, and 0xBD respectively.

- ~\uNNNN~ creates one character with Unicode code point NNNN.
  ~"\uFFFD"~ creates *one* character: U+FFFD (the replacement character).

These are not the same:

#+begin_example
(length "\xef\xbf\xbd")  ;; -> 3  (three separate characters)
(length "\uFFFD")         ;; -> 1  (one Unicode character)
#+end_example

The confusion arises because in UTF-8 file encoding, the bytes
EF BF BD represent U+FFFD. But Emacs Lisp ~\x~ escapes produce
characters by code point, not UTF-8 byte sequences. To match a
Unicode character in a regex while keeping the source file ASCII,
use ~\uNNNN~:

#+begin_example
;; WRONG -- matches three separate characters, not U+FFFD
(string-match "\xef\xbf\xbd" str)

;; RIGHT -- matches the single U+FFFD character
(string-match "\uFFFD" str)
#+end_example

* Local Elisp libraries in =lisp/=

Reusable Emacs Lisp lives under =~/.config/emacs/lisp/=. Emacs only puts
the config directory itself on ~load-path~ automatically, not
subdirectories, so ~init.el~ registers the folder once:

#+begin_example
(add-to-list 'load-path (expand-file-name "lisp" user-emacs-directory))
#+end_example

Each library file ~NAME.el~ must end with ~(provide 'NAME)~. Load it
with ~(require 'NAME)~. The feature name and basename must match:
~lisp/org-tools.el~ → ~(require 'org-tools)~.

Current libraries:

| File | Loaded from ~init.el~ | Role |
|------+----------------------+------|
| ~org-tools.el~ | Local-libraries ~autoload~; ~with-eval-after-load 'org~ ~require~ | Org buffer + export helpers (~scs/org-insert-creation-date~, line-prefix, …) |
| ~flycheck-org-lint-workaround.el~ | ~flycheck~ ~:config~ | Flycheck/org-lint line-cell advice |

Defer loading until dependencies exist. Org helpers use:

#+begin_example
(with-eval-after-load 'org
  (require 'org-tools))
#+end_example

because ~org~ is ~:defer t~ in this config. Interactive org-tools
commands are also ~autoload~ed under Local libraries so ~M-x~ and
~H-c d~ work before ~org~ is loaded; the first use loads ~org-tools~
(and ~org~ via ~require~).  Only those interactive entry points carry
~;;;###autoload~ cookies; export hook callbacks do not.

Flycheck helpers load
inside the flycheck ~use-package~ ~:config~ block:

#+begin_example
(use-package flycheck
  ...
  :config
  (require 'flycheck-org-lint-workaround)
  (scs/flycheck-setup-org-lint-workaround)
  (global-flycheck-mode))
#+end_example

Mark interactive commands with ~;;;###autoload~ so ~M-x~ and future
byte-compiled autoloads can see them before the file is loaded.  In this
profile, pair those cookies with explicit ~(autoload ...)~ forms under
Local libraries in ~init.el~ (cookies alone do not register at runtime).

Byte-compiled =~.elc~= files may appear after local byte-compilation but
must not be committed; =~/.gitignore~= lists ~*.elc~.

* Org property drawers and =scs/org-insert-creation-date=

~org-entry-put~ creates the drawer and sets the value; a follow-up pass
lowercases ~:properties:~, ~:end:~, and property keys so mixed-case
drawers in howm notes stay consistent. Drawer bounds are found by
searching the whole entry (not only at ~org-element~ ~:contents-begin~),
so a drawer is still found when body text precedes it; ~org-entry-put~
itself still inserts at the canonical position after the headline.

When locating drawers with regexps, use ~[ \t]*~ for indentation, not
~\s-*~. In Emacs regexps ~\s-*~ is a /syntax class/ (here the =~=
class), not “spaces”, so it can match the asterisk at the start of an
Org heading line.

* Hyper chords that macOS steals (Fn+C / Fn+H)

With ~ns-function-modifier~ set to ~hyper~ (Caps Lock remapped to Fn
via Karabiner), a Hyper chord is physically Fn+letter.  Recent macOS
releases steal some of those before Emacs:

| Chord | macOS action | Emacs want |
|-------+--------------+------------|
| Fn+C  | Control Center (Full Keyboard Access) | ~H-c~ prefix |
| Fn+H  | Show Desktop (also Fn-F11 / Cmd-Mission Control) | ~H-h~ delete |

Clearing the shortcut in System Settings sometimes helps and sometimes
does not stick; the reliable fix is the same Karabiner proxy pattern
for each stolen letter, plus a one-line Emacs translation.

** Prefix keymap (~H-c~)

A single-key global binding on ~H-c~ (for example ~org-capture~)
/fires immediately/ and prevents a two-key sequence such as ~H-c d~.
The fix is to make ~H-c~ a prefix keymap (~define-prefix-command~),
then bind follow-up keys on that map:

- ~H-c c~ → ~org-capture~
- ~H-c d~ → ~scs/org-insert-creation-date~ (Org buffers only; plain ~d~
  after the prefix — no second Caps/Fn press)
- ~H-c H-d~ → same command (Hyper ~d~ after the prefix also works)

The command signals ~user-error~ outside Org mode.

#+begin_example
(define-prefix-command 'scs/hyper-c-prefix-map)
(global-set-key (kbd "H-c") 'scs/hyper-c-prefix-map)
(define-key scs/hyper-c-prefix-map (kbd "c") 'org-capture)
;; (autoload ... "org-tools" ...) lives under Local libraries in init.el
(define-key scs/hyper-c-prefix-map (kbd "d") #'scs/org-insert-creation-date)
(define-key scs/hyper-c-prefix-map (kbd "H-d") #'scs/org-insert-creation-date)
#+end_example

** Progressive rub-out (~H-h~)

~H-h~ runs ~scs/hyper-h-rubout~.  "Rub out" means delete /before/
point (Backspace direction), not forward delete after point:

- First press: one preceding sentence, with
  ~sentence-end-double-space~ bound to nil for this command only.
  Emacs's default (double space after ~.~) would treat
  ~sentence 1. sentence 2. sentence 3.|~ as one sentence and wipe the
  line; single-space prose keeps only ~sentence 3.~ on the first press.
- Immediate second press: kill from ~line-beginning-position~ to
  point (rest of the preceding line), or another backward sentence
  if already at bol.

Text lands on the kill ring (~yank~ restores it).  The command resets
~this-command~ after the kill so a second ~H-h~ is still detected as
a repeat (~kill-region~ would otherwise rename ~this-command~).

Plain Backspace / =C-h= are /rub-out/ (before point) and stay
one-character.  Forward Delete (=C-d=, Fn-Backspace / =<deletechar>=)
runs ~scs/delete-forward~: if spaces or tabs follow point, remove that
whole run (so ~test|     test1~ becomes ~testtest1~); otherwise delete
one character.  =smart-delete-mode= stays disabled because it remaps
rub-out.

** Karabiner: stop macOS from seeing raw Fn+C / Fn+H in Emacs

Scope rules to ~org.gnu.Emacs~ so other apps keep normal Fn behaviour.
Each rule /consumes/ Fn+letter and re-emits a proxy chord macOS does
not treat as the system shortcut:

- *From:* Fn+C or Fn+H (Caps+letter with the usual Caps→Fn remap)
- *To:* that letter with physical Cmd+Ctrl+Opt held (no Shift)

Rule descriptions in =~/.config/karabiner/karabiner.json~:

- ~Emacs: Fn+C as C-M-s-c (avoid macOS Control Center on Fn+C)~
- ~Emacs: Fn+H as C-M-s-h (avoid macOS Show Desktop on Fn+H)~

#+begin_example
{
  "description": "Emacs: Fn+H as C-M-s-h (avoid macOS Show Desktop on Fn+H)",
  "manipulators": [{
    "type": "basic",
    "conditions": [{
      "type": "frontmost_application_if",
      "bundle_identifiers": ["^org\\.gnu\\.Emacs$"]
    }],
    "from": {
      "key_code": "h",
      "modifiers": { "mandatory": ["fn"], "optional": ["any"] }
    },
    "to": [{
      "key_code": "h",
      "modifiers": ["left_command", "left_control", "left_option"]
    }]
  }]
}
#+end_example

Other Hyper keys (Fn+X, Fn+B, …) still use ~ns-function-modifier~
unchanged unless macOS starts stealing them too.

** Emacs: translate the proxy chord back to Hyper

This config remaps physical modifiers before ~kbd~ sees them:

| Physical key | Emacs modifier |
|--------------+----------------|
| Command      | Control (~C~)  |
| Option       | Meta (~M~)     |
| Control      | Super (~s~)    |

So Karabiner’s Cmd+Ctrl+Opt+letter arrives as ~C-M-s-<letter>~
(lowercase ~s~ = Super).  Translate each proxy back in the ~darwin~
block:

#+begin_example
(define-key key-translation-map (kbd "C-M-s-c") (kbd "H-c"))
(define-key key-translation-map (kbd "C-M-s-h") (kbd "H-h"))
#+end_example

** Pitfall: ~C-M-S-c~ is not ~C-M-s-c~

In ~(kbd "...")~, uppercase ~S~ is /Shift/, lowercase ~s~ is /Super/.
An early attempt used ~C-M-S-c~ in ~key-translation-map~; Emacs then
reported ~C-M-s-c is undefined~ because the translation never matched.
Do not add a parallel Karabiner rewrite for Fn+D unless macOS steals
that too — ~H-c d~ uses plain ~d~ on the prefix map and needs no
Karabiner proxy.
